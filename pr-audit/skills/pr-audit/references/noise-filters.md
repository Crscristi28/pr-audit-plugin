# Noise filters

Files matching these patterns are removed from the diff **before** tier classification and subagent review. They are auto-generated, third-party, or otherwise not meaningful for code review.

Apply each pattern as a regular expression against the relative file path.

## Lock files

```
^bun\.lock$
^package-lock\.json$
^yarn\.lock$
^pnpm-lock\.yaml$
^Cargo\.lock$
^Gemfile\.lock$
^composer\.lock$
^poetry\.lock$
^Pipfile\.lock$
^go\.sum$
^flake\.lock$
^Podfile\.lock$
```

## Minified / bundled assets

```
.*\.min\.js$
.*\.min\.css$
.*\.bundle\.js$
.*\.bundle\.css$
.*\.map$
```

## Build output directories

```
^dist/.*
^build/.*
^out/.*
^\.next/.*
^\.nuxt/.*
^\.svelte-kit/.*
^\.vercel/.*
^\.cache/.*
^coverage/.*
^node_modules/.*
^vendor/.*
^\.venv/.*
^__pycache__/.*
^target/.*
```

## Binary / asset extensions

```
.*\.(png|jpg|jpeg|gif|webp|svg|ico|bmp|tiff)$
.*\.(mp3|mp4|wav|webm|ogg|mov|avi)$
.*\.(woff|woff2|ttf|eot|otf)$
.*\.(pdf|zip|tar|gz|rar|7z)$
.*\.(exe|dll|so|dylib|a)$
.*\.(jar|war|class)$
```

## OS / IDE artifacts

```
^\.DS_Store$
.*/\.DS_Store$
^Thumbs\.db$
.*\.swp$
.*\.swo$
^\.idea/.*
^\.vscode/.*
^\.zed/.*
```

## Generated file markers (content-based, not path)

The orchestrator additionally inspects the first 5 lines of each non-filtered file for these markers. If present, the file is treated as generated and excluded **unless** it is a database migration file.

```
^//\s*@generated
^/\*\s*@generated
^#\s*@generated
^<!--\s*@generated
//\s*Code generated by .* DO NOT EDIT
//\s*This file is auto-generated
```

**Exception**: files in `migrations/`, `drizzle/`, or `prisma/migrations/` are NEVER excluded even if marked generated. Database migrations are critical to review even when tooling stamps them as generated.

## Application order

1. Get the full diff via `gh pr diff` or `git diff`.
2. For each file in the diff, check path patterns in this file. Drop matches.
3. For each remaining file, check the first 5 lines for generated markers. Drop matches (except migrations).
4. The remaining file list is the **review scope**.

## Edge case: PR contains only noise

If after filtering, no files remain in scope, the orchestrator posts a single top-level comment: *"This PR contains only auto-generated or non-code files (lock files, build output, etc.). No code review performed."* and exits with an approve outcome. Tests, linters, or other CI tools may still find issues; this plugin's scope is code review.
